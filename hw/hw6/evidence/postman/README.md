# Postman Evidence — X-Student-Id

## Required evidence

Capture a real Postman Console screenshot showing all three of these items together:

1. Fully resolved request URL, for example `http://localhost:3000/api/register`.
2. Outgoing header `X-Student-Id: 23127334`.
3. ISO timestamp produced during the same request execution.

The screenshot must come from your actual Postman run. AI must not create, reconstruct, enhance or edit this screenshot.

## 1. Configure the environment

1. Select the local HW06 environment in the top-right environment selector.
2. Add or verify environment variable `studentId`.
3. Set both its initial/current value as appropriate for your local workspace to exactly:

```text
23127334
```

Do not include spaces or quotation marks in the value.

## 2. Add the collection-level pre-request script

1. Open collection `23127334_HW06_API_Testing`.
2. Select the collection itself, not an individual folder or request.
3. Open **Scripts** and select **Pre-request**. In older Postman versions, use the collection **Pre-request Script** tab.
4. Paste and save this script:

```javascript
const EXPECTED_STUDENT_ID = '23127334';

pm.environment.set('studentId', EXPECTED_STUDENT_ID);
const studentId = String(pm.environment.get('studentId') || '').trim();

pm.request.headers.upsert({
  key: 'X-Student-Id',
  value: studentId
});

const attachedHeader = pm.request.headers.get('X-Student-Id');
const timestamp = new Date().toISOString();
const resolvedUrl = pm.variables.replaceIn(pm.request.url.toString());

pm.test('Pre-request: X-Student-Id is attached and correct', function () {
  pm.expect(studentId, 'environment studentId').to.eql(EXPECTED_STUDENT_ID);
  pm.expect(attachedHeader, 'outgoing X-Student-Id header').to.eql(EXPECTED_STUDENT_ID);
});

console.log('[HW06 REQUEST EVIDENCE]', {
  timestamp,
  method: pm.request.method,
  url: resolvedUrl,
  'X-Student-Id': attachedHeader
});
```

The script runs for every request below the collection. `upsert` ensures the outgoing request has one effective `X-Student-Id` header, and the pre-request assertion confirms the attached value before the request is sent.

## 3. Open Postman Console

Use either method supported by your Postman version:

- Bottom-left toolbar: click **Console**.
- Application menu: **View → Show Postman Console**.

Keyboard shortcuts commonly available:

- Windows/Linux: `Ctrl + Alt + C`.
- macOS: `Cmd + Option + C`.

Keep the Console visible before sending the request so the complete log entry is retained.

1. Start the EShop backend at `http://localhost:3000`.
2. Select any actual request in the collection, preferably a stable setup request or `POST {{baseUrl}}/api/register` with controlled data.
3. Confirm the correct environment is selected.
4. Click **Send** once.
5. In Postman Console, locate the `[HW06 REQUEST EVIDENCE]` log entry for that send.
6. Expand the logged object if necessary. It must visibly contain values equivalent to:

```text

```

The exact timestamp must be generated by your run. Do not copy the example timestamp into evidence.

## 5. Verify the actual outgoing header

The custom console object proves what the pre-request script read back. Also expand the same request's network entry in Postman Console and inspect **Request Headers**. Confirm:

```text
X-Student-Id: 23127334
```

If the network entry shows two student headers, remove any manually configured duplicate at request/folder level and rerun. The saved collection-level script should be the single source of this header.

The request result should also show the assertion named:

```text
Pre-request: X-Student-Id is attached and correct
```

as passed. A failed assertion means the run is not valid evidence even if the server returned a response.
